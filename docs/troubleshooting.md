##### 문제: API 키를 코드에 직접 작성하여 깃허브에 노출되는 보안 이슈 발생.
- 해결: 노출된 키를 즉시 폐기 및 재발급. python-dotenv를 도입하고 .env 파일을 .gitignore에 등록하여 형상 관리에서 제외함으로써 보안성 강화.

##### 문제: .gitignore 적용 전에 커밋된 data 폴더가 깃허브에 그대로 푸시되어 데이터가 올라가는 문제 발생.
- 해결: git rm -r --cached data/ 명령어를 사용하여 로컬 데이터는 보존하고 Git의 추적 인덱스(캐시)에서만 제거한 뒤 재커밋하여 해결.

##### 문제: 주피터 노트북(notebooks 폴더 내부)에서 os.getcwd()를 기준으로 data/ 폴더에 접근하려다 FileNotFoundError 발생.
- 해결: os.path.dirname()을 활용해 현재 실행 중인 스크립트의 상위 디렉토리(프로젝트 루트)를 동적으로 찾고, 그 위치를 기준으로 절대 경로를 병합(os.path.join)하여 해결.

##### 문제: API로 수집한 공시 데이터에 리스크 분석과 무관한 임원 주식 거래 공시가 너무 많이 포함됨.
- 해결: 데이터 탐색(EDA) 결과, 무관한 공시는 flr_nm(제출인명)이 개인(임원)으로 되어 있음을 발견. flr_nm == corp_name 조건을 적용하여 1차 노이즈 필터링 완료.

##### 문제: 50개 기업의 데이터를 API로 연속 호출 시, Rate Limit(호출 속도 제한) 초과 에러 및 중간에 빈 데이터 발생으로 인한 전체 파이프라인 중단 우려.
- 해결: time.sleep(0.5)를 도입하여 서버 부하를 방지하고, try-except 블록과 disclosures.empty 체크 로직을 추가하여 단일 기업의 에러가 전체 파이프라인을 멈추지 않도록 견고성(Robustness) 확보.
