# 🛠️ Troubleshooting Guide

AI Investment Risk Detector 프로젝트를 진행하며 발생한 주요 이슈와 해결 과정 기록

## 1. DART API 데이터 파이프라인 이슈
* **[이슈 1] 비상장사 대량 로드 문제:** DART API가 비상장사의 종목코드를 Null이 아닌 공백으로 반환하여 11만 개의 데이터가 잘못 로드되는 현상 발생.
  * **[해결]:** `notna()` 검사 후 `str.strip() != ""` 조건을 추가하여 약 3,500개의 실제 상장사만 메모리에 적재하도록 최적화.
* **[이슈 2] BeautifulSoup XML 파싱 경고:** OpenDART 원문이 XML 구조임에도 `html.parser`를 사용하여 호환성 경고 발생.
  * **[해결]:** 빠르고 정확한 XML 전용 파서인 `lxml` 패키지를 설치하고 구문 분석 엔진을 `'xml'`로 교체하여 해결.
* **[이슈 3] 정정 공시 중복 집계 (Double Counting):** 기업의 단순 정정 공시가 새로운 악재로 인식되어 벌점이 두 배로 부과되는 로직 오류 발견.
  * **[해결]:** 공시의 제목인 보고서명(`report_nm`) 컬럼에 `[기재정정]`, `[첨부추가]`가 포함되거나, 특이사항 약어인 비고(`rm`) 컬럼에 '기'가 표시된 중복 문서를 정규표현식으로 사전 차단.

## 2. 사용자 검색 UX 이슈
* **[이슈 1] 한/영 기업명 검색 불일치 (404 Error):** DART에 'NAVER'로 등록된 기업을 사용자가 '네이버'로 검색 시 찾지 못하는 문제 발생.
  * **[해결]:** 자주 헷갈리는 기업명에 대한 별명(Alias) 딕셔너리를 구축하고, 이름 대신 숫자 6자리 종목코드(`isdigit()`) 검색 기능을 함께 지원하여 UX 대폭 개선.

## 3. KR-FinBERT NLP 딥러닝 이슈
* **[이슈 1] AI 언어모델 토큰(Token) 길이 제한:** BERT 모델 아키텍처 특성상 한 번에 최대 512개의 토큰만 처리 가능하여 긴 원문을 한 번에 분석 시 에러 발생.
  * **[해결]:** 공시의 고유 문서 번호인 접수번호(`rcept_no`)를 통해 수집한 텍스트를 500자 단위로 쪼개어 반복 추론하는 Chunking 기법 도입. 분할된 문맥 중 가장 높은 부정(Risk) 확률을 최종 점수로 채택.
* **[이슈 2] 의례적 경고문에 의한 False Positive (오탐지):** 현대차 등의 '증권발행실적보고서' 내에 기재된 법적 투자위험요소(부도, 원금 손실 등)를 AI가 실제 악재로 오인하여 100점의 패널티를 부과.
  * **[해결]:** 억울한 패널티를 유발하는 `증권발행실적`, `투자설명서` 등의 보고서명(`report_nm`)을 정규표현식 필터링에 추가하여 분석 대상에서 원천 제외.

## 4. 인프라 및 배포(MLOps) 이슈
* **[이슈 1] 배포 시 로컬 경로 의존성 에러:** `pip freeze`로 생성한 `requirements.txt`에 로컬 PC의 파일 경로가 포함되어 클라우드(Render) 빌드 실패.
  * **[해결]:** 프로젝트 구동에 필수적인 패키지(fastapi, torch, transformers 등)만 명시한 클린 버전의 `requirements.txt`로 재작성하여 해결.
* **[이슈 2] 무료 클라우드 환경 OOM (Out Of Memory) 발생:** Render(Free Tier) 배포 중 `Out of memory (used over 512Mi)` 에러와 함께 서버가 종료됨.
  * **[원인/해결]:** Render 무료 인스턴스의 512MB 한계 대비 AI 언어모델 적재 시 약 800MB 이상이 요구됨을 확인. 상용화 시 AWS EC2 등으로 스케일업이 필요함을 문서화하고 시연은 Localhost로 롤백 진행.
* **[이슈 3] 프론트엔드 무한 로딩 및 CPU 연산 병목:** 백엔드 응답 지연 시 화면이 멈추거나, 로컬 CPU 환경에서 'LG전자'와 같이 대량의 공시를 분석할 때 타임아웃 발생.
  * **[해결 1 (우아한 실패)]:** 프론트엔드 `requests` 요청에 `timeout` 예외 처리를 추가하여 사용자에게 명확한 에러 메시지(응답 지연) 제공.
  * **[해결 2 (텍스트 샘플링)]:** 무조건 1분 이상 걸리는 긴 텍스트를 최적화하기 위해, 문서가 아무리 길어도 서론 부분 최대 5개 조각(`[:5]`)까지만 읽도록 Truncation 기법을 적용하여 연산 시간을 획기적으로 단축.
